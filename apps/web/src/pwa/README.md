# PWA Release and Update Notes

The service worker is generated by `vite-plugin-pwa` during production builds. It uses
prompt updates: a new worker waits until the user explicitly chooses **Update now**.
The update coordinator checks once after registration, when the app becomes visible, and
every 45 minutes while open. Failed checks are ignored so they cannot interrupt field work.

Editable Technician forms, New Service Visit, Manager Customer Configuration, and the
development workspace are unsafe update routes. Unknown routes are unsafe by default. They
show the update notice but never an update action. The user must save/submit as appropriate
and return to a safe screen first. The coordinator registers the `vite-plugin-pwa`-generated
worker with Workbox's public client API and sends the standard `SKIP_WAITING` message only
after an explicit action. This avoids the virtual plugin helper, which always installs a
global controller-change reload listener when a worker is waiting.

The coordinator owns controller-change policy per browser client. Only the client that asked
to activate an update may reload automatically, and only if its *current* route is still safe
when control changes. Every other client, and any client now on an unsafe route, stays open
with a pending notice and an explicit **Reload to finish update** action on a safe screen.
An activation watchdog re-enables the action if the waiting worker does not take control.

Do not use automatic `skipWaiting`, `clientsClaim`, cache clearing, service-worker
unregistration, or forced reloads for releases. Cache Storage is only for app-shell assets.
Business data, drafts, sync outbox items, offline reference data, and attachment Blobs stay
in IndexedDB and are never cleared by an application update.

Production builds expose a `Build: ...` identifier. Docker assigns a UTC build timestamp;
local builds fall back to the package version. Caddy must keep HTML and `sw.js` revalidating
while retaining immutable current and previous hashed assets. Manual release acceptance is:

1. Keep an unsaved edit open during an A → B deployment and confirm the form does not reload.
2. Save the draft, return to My Service Jobs, choose **Update now**, and confirm B loads once.
3. Confirm saved drafts, pending outbox items, and attachment Blobs remain, including offline.
